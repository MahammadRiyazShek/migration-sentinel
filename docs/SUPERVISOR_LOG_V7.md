# Supervisor log, seventh session: the audit that reads prose

**Instruction given:** the same as sessions three, five and six. Take the finished v5/v6 submission and
the form text, find the assumptions it does not know it is making, try to make its claims false, then
fix what breaks. Sandboxed Python shell, no network, no API key, no credentials.

**What did not break.** Everything the repository publishes reproduced on the first run, from the
archive, on a clean container:

| command | result | measured wall clock |
|---|---|---|
| `python3 -m unittest discover -s tests` | `Ran 33 tests ... OK` | 0.26 s |
| `python3 eval/run_eval.py --ablations` | 108 reviews, tables identical to the committed ones | 0.73 s |
| `python3 eval/model_invariance.py` | 180 reviews, `surface_changed` 0/12 on all 15 arms | 1.62 s |
| `python3 eval/time_sensitivity.py` | 6 constant sets, band -12% to 69% | 0.1 s |
| `python3 tools/check_results.py` | **27/27 claims hold**, including `12/12` recorded packets matching a fresh reference run | 0.4 s |

Python 3.12.13, standard library only, no `pip install`, no network. So the numbers were not the place
to attack. The defects were all in the layer no audit in this repository could see.

---

## 1. Critique layer: three assumptions the submission was still making

**A1 - that everything worth auditing is a number in `results/*.json`.** `tools/check_results.py` is
the spine of the reproducibility claim and it reads JSON. Four of the five defects below are prose,
and it could not have caught one of them. The repository had 33 tests and 27 audited claims, and zero
checks on the first page a judge opens.

**A2 - that a runtime figure written in prose stays true.** The superseded entry point asserted the
invariance harness took "~4 s" and the suite "under 10 seconds"; measured here they are 1.6 s and
about 3 s in total. Nobody re-measures a sentence. The results tables are regenerated by a script,
so their numbers cannot drift; every figure typed into a paragraph can.

**A3 - that the ground truth is stable because one person wrote it.** Twelve cases, one schema, hand
labels. Every headline metric divides by that, and the only sensitivity band in the repository is for
the reviewer-minute constants. `README.md` says "do not quote the F1 without its denominator", which
is honest about the size of the denominator and silent about the fact that its labels have never been
disagreed with by a second party. This session did not fix it: writing a second opinion on my own
ground truth is exactly the self-grading the disclosure refuses.

---

## 2. Variation operator: two radically different shapes for the same fix

**V-A, rejected: make the audits a CI gate instead of scripts.** GitHub Actions running the suite on
every push, with a badge in the README. Rejected for this submission: it moves the proof off the
judge's machine and onto a service, and the whole reproducibility argument here is that a judge with
no key and no network re-derives every number locally in about three seconds. A green badge is
somebody else's assertion. `python3 tools/check_results.py` is the judge's own.

**V-B, deferred and written down instead: replace the hand ground truth with differential testing.**
Generate migrations and query corpora programmatically, and label hazards by what a real Postgres
container actually does under `lock_timeout` and a live corpus, so the labels stop being my opinion.
This is the honest answer to A3 and it is out of scope for one window: it needs Docker and a network,
which breaks the zero-dependency promise that makes the rest of this reproducible. Recorded as the
next experiment rather than half-built.

**Chosen: a prose audit with an exit code.** `tools/check_docs.py`, standard library, five checks. It
is the smallest thing that turns A1 from a habit into a failure.

---

## 3. What broke, and what shipped

**D1 - two rival entry points.** `JUDGE_START_HERE.md` (v6) and `JUDGES_START_HERE.md` (v5) both sat
at the root, both titled "Judges start here", with different command lists, different command order
and different runtime claims. The submission form text says "start at `JUDGE_START_HERE.md`", so which
page a judge read depended on which filename they guessed. **Fix:** the v6 page is canonical, the v5
page is deleted, nothing referenced it. `check_docs.py` now fails if a second one ever appears.

**D2 - mis-decoded characters in the newest page.** Three table cells in `JUDGE_START_HERE.md` and one
line in `docs/SUPERVISOR_LOG_V6.md` rendered a section sign as UTF-8-read-as-Latin-1, in the rubric
map, which is the first table a judge reads. **Fix:** repaired, and the audit now scans every authored
file for the seven usual mis-decoding sequences.

**D3 - the v6 log announced a file the archive did not contain.** `docs/SUPERVISOR_LOG_V6.md` lists
`SUBMISSION_DESCRIPTION.md` under "Files added". It was not there. That is precisely the class of
defect `tools/collect_agent_traces.py` was built to prevent for traces and `check_results.py` for
numbers: a claim about the repository that the repository contradicts. **Fix:** the file now exists,
holds the verified paste-ready form text, and the audit asserts both that it exists and that the
pasteable region is inside the form's 10,000-character limit (it is 9,587).

**D4 - a generated sentence contradicted its own table.** `results/time_sensitivity.md` read "The sign
never reverses, except in the flagged row" while **two** rows are flagged `(claim reverses)`. The
generator in `eval/time_sensitivity.py` was written when one set reversed, and the sixth session's
constants made it two without touching the conditional. A judge reading closely sees a document
hedging about its own worst number. **Fix:** the generator now states the count and says plainly that
under those constants a baseline is faster than the pipeline and the claim as written is false. The
table never lied; only the paragraph did.

**D5 - the pitch buried the honest reading of a tied primary metric.** The form text published
"blind-spot cases cleared: 0/2, 0/2, 0/2" as a primary metric, which reads as no improvement at all.
The reason the baselines tie is that they request changes on 10 and 11 of 12 migrations, including the
one that is genuinely safe, so they clear nothing and name zero blind spots, while Sentinel holds 0/2
*and* approves the clean case. That was in `results/`, not in the pitch. **Fix:** stated in the
description, with the numbers, next to the tie.

**Not touched, by design:** the twelve cases, the ground truth, the hazard vocabulary, the scorer, the
reviewer-minute constants, the five agents, the coverage ledger and the narrator. No detection metric
moved. `tools/check_results.py` still reports 27/27, and the 33 tests still pass, after every edit
above.

## 4. Three mistakes in this session's own first attempt

**M1 - my first reference checker was mostly wrong.** It resolved paths relative to the file and to
the repository root only, and flagged nine legitimate references as broken: docs write
`prompts/cartographer.md` under a heading that already named `sentinel/agents/prompts/`, and
`DEPLOY.md` writes `data/bundle.json` while describing the inside of `site/`. An audit whose failures
are mostly false is an audit that gets ignored, which is worse than no audit. The resolver now accepts
a suffix match anywhere in the tree, and the one genuinely unresolvable reference
(one path collapsing the V3, V4 and V5 logs into a single slash-separated shorthand) was expanded in the source document
rather than excused in the checker.

**M2 - I wrote a non-English word into the paste-ready description** from a bad token, and read past it
twice. It was caught by an explicit non-ASCII scan, not by proofreading, which is D2's lesson turned
on the session that found D2: prose defects need machines, including mine.

**M3 - my first instinct was to add these as claims 28 to 31 in `tools/check_results.py`.** That would
have put documentation checks inside the results audit and made "27/27" mean something different in v7
than it means in v5 and in the video, for no gain. The audits stay separate: `check_results.py` counts
claims about measurements, `check_docs.py` counts claims about the repository.

---

## 5. The lesson, stated as the next rule

The sixth session's finding was that a defence audited in its own vocabulary reports on the attacker's
imagination. This session is the same shape one layer out: **a repository that audits only its
measurements is audited only where it already knows how to be wrong.** The five defects here were a
duplicate entry point, four broken glyphs, an announced file that did not exist, a generated sentence
that contradicted its own table, and a tie presented without its explanation. Not one is a number, and
every one of them is on the path a judge walks before reaching a number. Point an exit code at the
artefact your reader actually opens first.
