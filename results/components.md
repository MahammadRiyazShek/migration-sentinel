## Did each component do the job it was added for?

- **minus shadow replay (rules only)** — predicted to protect *unsafe approvals*. Removing it costs: unsafe approvals +1 (earns it); strict recall +0.394 (earns it); severity agreement +0.022 (earns it); verified plans +12 (earns it); reviewer minutes/case +14.1 min (earns it).
- **minus static rules (replay only)** — predicted to protect *unsafe approvals*. Removing it costs: unsafe approvals +2 (earns it); strict recall +0.637 (earns it); severity agreement -0.031 (argues against it); reviewer minutes/case -0.4 min (argues against it).
- **minus incident memory** — predicted to protect *severity agreement*. Removing it costs: severity agreement +0.031 (earns it).
- **minus verifier + retry loop** — predicted to protect *verified plans, reviewer minutes*. Removing it costs: verified plans +12 (earns it); reviewer minutes/case +14.1 min (earns it).
- **minus coverage gate (the v1 behaviour)** — predicted to protect *coverage-gap cases cleared without a sign-off*. Removing it costs: gap cases cleared without a sign-off +1 (earns it); reviewer minutes/case -0.7 min (argues against it).

Two components (replay, static rules) are load-bearing on the primary metric. One (the verifier) is load-bearing on everything downstream of detection and worth nothing to detection itself. One (incident memory) is close to free on this case set, which is a statement about the case set as much as about the component: 12 cases contain one recurrence, so one severity is all it can possibly move.

The coverage gate is the only component that makes the pipeline look *worse* on a published metric. It moves no detection number at all and it adds modelled reviewer minutes, because every gap it opens is a human decision someone has to make. What it buys is the one thing the other four cannot: a verdict that stops short of clean when the review has a blind spot on an object the migration touches. Removing it is the v1 behaviour, and the v1 behaviour clears one.
